## 3. 앞으로 필요한 지표

가장 급한 건 PR #149로 들어간 Kanana vLLM의 폴백 비율과 품질 비교이고, 본인인증 정확도는 사용자 의견이 아니라 정답이 붙은 평가셋으로 잽니다.

### 본인인증 사용자 의견 수집 선택지

결정(2026-10-19): A + D로 갑니다. B·C는 지금은 하지 않고, 신고가 쌓이면 C를 다시 검토합니다. 어느 선택지도 FAR(타인이 통과한 경우)은 잡지 못하므로 FAR은 평가셋으로만 잽니다.

| 선택지 | 사용자에게 보이는 것 | 얻는 지표 | 필요한 것 | 한계 |
| --- | --- | --- | --- | --- |
| A. 신고 버튼 1개 (채택) | 실패 화면에 "본인인데 실패했어요" 버튼 | 실패 중 신고 비율 (FRR 보조 신호) | 버튼 + 이벤트 로그, 유사도 점수 함께 기록 | 원인을 모름, 신고하지 않는 사람은 안 잡힘 |
| B. 실패 사유 선택 | 실패 화면에 사유 3\~4개 선택 (본인 맞음 / 조명·각도 / 안경·마스크·가림 / 등록 사진이 오래됨) | 사유별 실패 분포 → 기준값 문제인지 촬영 환경 문제인지 구분 | A + 선택지 UI, 사유 코드 정의 | 사용자 응답률이 낮을 수 있음, 자기 보고라 부정확 |
| C. 수동 검토 요청 (이의 제기) | "검토 요청하기" → 운영자가 두 사진을 직접 확인 후 결과 안내 | 사람이 판정한 정답 라벨 → FRR 실측, 평가셋 자동 축적 | 사진 보관 동의, 검토 인력·화면, 처리 기준 | 운영 비용이 가장 큼, 개인정보 처리 절차 필요 |
| D. 의견 없이 로그만 (채택) | 변화 없음 | 실패 후 재시도 성공률, 유사도 분포 변화 | 인증 시도마다 결과·유사도·시도 횟수 로그 | 간접 신호라 실패 원인과 정확도는 추정만 가능 |
